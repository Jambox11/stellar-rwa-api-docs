# Dividends API

The dividends endpoints expose the on-chain dividend distribution contract. A distribution pays out a `payment_token` (any SEP-41 token) to holders of an `asset_token` proportionally to their balance at the time the distribution was created.

All amounts are `i128` values serialized as decimal strings to avoid precision loss in JSON.

## Distribution object

```json
{
  "id": 1,
  "asset_token": "CBMCWLSQSWUTLUJFCNBHNBSXMUM3XU7NAQ5TSNERW4HA4ZZBYHLG4ECZ",
  "payment_token": "CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC",
  "total_amount": "100000000000",
  "distributed": "25000000000",
  "claimed_percent": 25.0,
  "overflow_detected": false,
  "completed": false,
  "created_at_ledger": 3510000
}
```

| Field | Type | Description |
| --- | --- | --- |
| `id` | number | Distribution identifier |
| `asset_token` | string | Contract address of the asset whose holders receive dividends |
| `payment_token` | string | SEP-41 token contract used for payouts |
| `total_amount` | string (i128) | Total amount funded for the distribution |
| `distributed` | string (i128) | Amount claimed so far |
| `claimed_percent` | number | `distributed / total_amount` as a percentage (0–100) |
| `overflow_detected` | boolean | Set when a payout overflowed and needs manual reconciliation |
| `completed` | boolean | True once the distribution is fully claimed or finalized |
| `created_at_ledger` | number | Ledger at which the distribution was created |

## List distributions

`GET /api/dividends?asset_token={address}&page={page}&limit={limit}`

Returns a paginated list of distributions for an asset. Pagination is cursor-free: `page` is 1-based and `limit` defaults to `20` (max `100`).

```bash
curl "https://api.example.com/api/dividends?asset_token=CBMCWLSQSWUTLUJFCNBHNBSXMUM3XU7NAQ5TSNERW4HA4ZZBYHLG4ECZ&page=1&limit=20"
```

```json
{
  "data": [ /* Distribution objects */ ],
  "page": 1,
  "limit": 20,
  "total": 1
}
```

## Get a distribution

`GET /api/dividends/{id}`

Returns a single `Distribution` object, or `404` if it does not exist.

## Create a distribution

`POST /api/dividends`

```json
{
  "asset_token": "CBMCWLSQSWUTLUJFCNBHNBSXMUM3XU7NAQ5TSNERW4HA4ZZBYHLG4ECZ",
  "payment_token": "CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC",
  "total_amount": "100000000000",
  "deadline_ledger": 3600000
}
```

`deadline_ledger` is optional. When set, holders can only claim until that ledger; afterwards the creator may reclaim the unclaimed remainder.

## Batch operations

`POST /api/dividends/batch`

Create multiple distributions in a single transaction. Each entry uses the same body as `POST /api/dividends`.

```json
{
  "distributions": [
    {
      "asset_token": "CBMCWLSQSWUTLUJFCNBHNBSXMUM3XU7NAQ5TSNERW4HA4ZZBYHLG4ECZ",
      "payment_token": "CDLZFC3SYJYDZT7K67VZ75HPJVIEUVNIXF47ZG2FB2RMQQVU2HHGCYSC",
      "total_amount": "100000000000"
    }
  ]
}
```

`POST /api/dividends/{id}/claim-batch` claims on behalf of multiple holders in one call:

```json
{
  "holders": [
    "GAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAWHF"
  ]
}
```

## Claim

`POST /api/dividends/{id}/claim`

Claims the caller's share of a distribution. The caller must hold the `asset_token` and satisfy the contract's minimum holding period (see below).

## Minimum holding period

`GET /api/dividends/min-holding-period`

Returns the minimum number of ledgers a holder must have held the asset before claiming.

```json
{ "min_holding_period": 17280 }
```

`PUT /api/dividends/min-holding-period` (admin only) updates the value:

```json
{ "min_holding_period": 17280 }
```

## Deadline, reclaim, and cancel

- `POST /api/dividends/{id}/reclaim` — after `deadline_ledger` has passed, the creator reclaims the unclaimed remainder.
- `POST /api/dividends/{id}/cancel` — the creator cancels a distribution before any claims have been made; the full `total_amount` is refunded.

Both return the updated `Distribution` object.

## Admin handover

`POST /api/dividends/admin/transfer`

Initiates a two-step admin handover. The new admin must accept before the change takes effect.

```json
{ "new_admin": "GAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAWHF" }
```

`POST /api/dividends/admin/accept` — called by the pending admin to complete the handover.

`GET /api/dividends/admin` returns the current admin and any pending admin:

```json
{
  "admin": "GAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAWHF",
  "pending_admin": null
}
```

## SEP-41 payment tokens

Any SEP-41 compliant token can be used as `payment_token`. The contract calls `transfer` on the token when a holder claims, so the token must be deployed and the distribution contract must be funded before claims succeed. Use the token's `balance` entry point to confirm funding.
